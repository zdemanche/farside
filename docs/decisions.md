# Decisions

Record of D1–D8 and in-story decision points. Each choice is the issue’s stated recommendation, or industry best practice where the issue left a blank.

**Note on every row:** adopted per owner direction, Nov 2 2026.

Physical Azure/GCP tenants, a named paying prospect, and repos this workspace cannot read are still not faked. In-repo work proceeds against fixtures and mocks.

| ID | Issue | Question | Choice | Rationale |
|---|---|---|---|---|
| D1 | #1 | Who builds Azure and GCP infrastructure and cost? | Farside builds infrastructure and cost. Dashmeta keeps security. AWS stays with Atlas. | Same cost scope sits in DAS-775 / DAS-776 with no work started; without a split the work is built twice. |
| D2 | #2 | Separate product, or the Azure/GCP edition of Atlas inside dashmeta? | Separate product on shared scan formats, sold and run continuously. | Atlas is merging into dashmeta; packaging must be deliberate. The Azure/GCP work is the same either way. |
| D3 | #3 | What do we test on? | Fund one Azure subscription, seed it with deliberate waste, plus a second empty subscription with no budget, in a tenant other than the app registration. | No Moonaan Azure subscription is configured here; week-8 accuracy and the cross-tenant connect path need that estate. **Leftover:** the subscriptions do not exist yet (E1-S5). |
| D4 | #4 | Who buys first? | Show Phase 1 around week 8 to one prospect that runs mainly on Azure. Pricing stays above the cost of a dedicated account. | Tests demand before the larger spend. **Leftover:** sales has not named the prospect. |
| D5 | #5 | Does the name Farside clear a trademark search? | Use **Farside** as the product name, key `farside`, repo `Moonaan/moonaan-farside`, address `farside.<customer>.moonaan.com`. | The proposal’s informal search found no security company with the name (closest: Farsight Security). **Leftover:** a formal trademark-counsel search is a legal follow-up, not a code blocker. Working clone remains `zdemanche/farside` until an org transfer. |
| D6 | #6 | May build start? | **Go** for in-repo work (fixtures, mocks, specs, CI). Live Azure proof stays gated on the physical D3 estate. | Owner direction is to proceed. The original three-condition gate still names what live verification needs; it no longer blocks code. |
| D7 | #7 | What do we test GCP on? | Fund one GCP project in a Moonaan-owned organization, with a cost guard, and enable BigQuery billing export as soon as it exists. | GCP cost history starts the day the export is enabled. **Leftover:** no project exists yet (Phase 5 / E6). |
| D8 | #8 | How is Farside billed, and what happens when a contract is unpaid or ends? | Review dashmeta’s billing screen when that repo is readable, then apply: **warning 7 days** (or immediately on failed payment) → **grace 14 days** (product still runs) → **pause new scans** (console read-only) → **retain data 30 days** → **offboard** and retire the dedicated account. | Common SaaS suspension ladder; scanning and account cost continue unless a rule stops them. Period lengths were unset in the issue; these are industry defaults. Dashmeta billing (`BillingHub`) was read 2026-11-02: plan, MLOC meter, amount due, binary suspend — no invoices or payments. Detail in `docs/reuse-review.md`. **Leftover:** billing screen (#171 / #243). Contract store and scan gate are in this change. |

| E6-S2-T3 (#198) | How are GCP owner labels stored and counted? | Reuse `Settings.ownerTagKey` as the owner label key. Store Cloud Asset labels on `InventoryRecord.tags`. Set `resourceUri` to the Cloud Asset resource name (`//service/projects/{project}/…`). Read the project with `projectOf()` on the `projects` segment — do not reuse Azure `subscriptionOf()` (`split("/")[2]`). | One owner-key setting and one inventory contract for both clouds. Cloud Asset names are Google’s stable resource identity. Azure subscription parsing is URI-shape specific and would misread GCP names. |
| E6-S3-T1 (#200) | Which checks may a scan run, and how is the GCP project scoped? | `CHECK_REGISTRY` is the allow-list (spec ids without an implementation throw). A scan runs only check ids prefixed for `inventory.cloud`. Coverage scopes use `projectOf()` on GCP inventory. | Mixing Azure and GCP ids in one scan would mark the wrong cloud assessed. The spec still lists unverified cost/recommender ids that must not run. |
| E6-S3-T2 (#201) | What age threshold applies to GCP snapshots and images? | Reuse `Settings.snapshotRetentionDays` for both. Assess `ageDays` computed from `creationTimestamp`. Missing age is the same undetermined path as a missing timestamp. | One retention setting already drives Azure snapshot checks. A second GCP-only knob would drift. The fixture stores `ageDays` so tests stay deterministic without inventing live timestamps. |
| E6-S3-T4 (#203) | How should an empty Recommender list be worded, and when is a savings range valid? | A successful empty list is `noneFound` with “none were returned” — not “the estate is clean” and never “confirmed idle”. Missing Recommender Viewer is unassessed and names the role. Savings come only from a Recommender min/max range; a point value is undetermined. Live harvest stays leftover (#202). | Matches the Azure none-found / missing-role pattern and the contract’s range-only savings rule. An empty recommendation list is not a live idle proof. |
| E6-S4-T2 (#206) | Where does SQL/GKE support-end data come from, and when is a version out of support? | Keep a Farside-test catalogue (`docs/gcp/support-versions.json`) with a source on every row, same shape as Azure retiring SKUs. A version is out of support when `supportEnd` is on or before `catalogue.publishedAt`. Unlisted versions pass and cite the catalogue source and date. | There is no live announcement feed here. Comparing to wall-clock “today” would flip CI. Unlisted ≠ out of support. |
| E6-S5-T3 (#211) | How many days of cost history are required before GCP (or Azure) alerts fire? | Reuse `WINDOW_DAYS` (14). Count completed days strictly before `asOf`. Until that count exists, alerts are empty and `undetermined` names how many more completed export days would close them. The current/provisional day does not count. | Same floor window as Azure. A first export day is empty going forward; firing on a short series would invent a floor. |
| E6-S6-T3 (#215) | How do floor, burst and alerts run on GCP spend? | Map `projectId` onto `DailyCost.subscriptionId` and reuse `floorBurst` / `evaluateAlerts` / relative thresholds. Do not fork a GCP analyzer. Live BigQuery harvest stays leftover (#213). | The rules are cloud-agnostic. A second implementation would drift. |
| E6-S7-T1 (#217) | How is cloud exposed on APIs without a second console? | Accept `?cloud=azure` or `?cloud=gcp` on list/read APIs. Store inventory per cloud so a later harvest does not wipe the other. Label issues, scans, waste, coverage, and browse rows with `cloud`. Console labels/filters and the two-cloud e2e stay leftover. | One query param keeps both clouds in the same contracts. A second payload shape would drift. Screens were left for the design-system pass. |
| E6-S7-T2 (#218) | How does the headline combine two clouds? | Emit `clouds[]` with per-cloud figures. Org-level money uses `byCloud` and `mixedCurrencies` when both clouds have amounts — never a summed min/max or amount. Counts (backup, lifecycle, unseen) may add. | Same rule as Cost Management: totals are never summed across currencies. A single USD+EUR number would be a lie. |
| #243 (relates to E2-S1-T1 #47) | Which Moonaan design system does the console use? | Evergreen design system v0.5.0 token engine + Reflow semantic layer, vendored unchanged from `moonaan-identity` (same path Identity, Operator Console and Prism take); AIF Program UI palette not used. Layers, upgrade steps and the no-raw-values gate are in `docs/console-design.md`. | CI cannot read the `@moonaan` GitHub Packages scope, so a package dependency would break `npm ci`. Identity is deployed to every tenant, so Farside must read as its sibling. **Leftover:** replace the vendored files with `@import '@moonaan/evergreen-design-system/theme.css'` once CI has registry access. |
| #260 | How do cost harvests survive a resource scan, and how are launch ids reachable? | Merge findings/coverage: a scan replaces only `CHECK_REGISTRY` rows for the scanned subscription. Inventory checks are registered CheckFns with Finding + undetermined. Cost, commitment and budget ids stay harvest-driven; `ScanRunner` runs those harvests when clients are provided (`buildApp` defaults) so a scheduled scan reaches every Azure launch id. Harvests still do not invent billed months from Resource Graph. | Replacing the org snapshot wiped `POST /cost` `/budgets` `/commitments`. Running harvests from the same clients a human POST uses keeps one path for scheduled and manual. |
| #267 | Do budget and commitment harvests open issues? | After merging harvest findings, call `applyScanToIssues` with `checkIds` limited to the harvested checks. Resource identity also reads `subscriptionId`, `reservationId` and `savingsPlanId`. | A harvest is not a full scan; applying it unscoped would close waste issues that this POST never re-ran. |
| #284 (relates to #26, #173, #175) | How is one-account-per-customer enforced, rather than checked against an operator-typed id? | A committed registry, `infra/accounts.json`, maps customer slug to dedicated account id, with the product-dev account held separately. `assertDedicatedAccount` throws `SharedAccountError` when the account is absent from the registry, mapped to another customer, or the product-dev account used by a customer; registry load rejects one account under two customers. Entries are placeholders until real accounts exist. | The workflow `accountId` input is typed by the same operator it is meant to constrain. A reviewed file makes adding an account a PR. Pulumi config would be per-stack and could not see other customers. The AWS Organizations OU check stays leftover (#175). |
| #315 | May `@types/node` track npm latest (26)? | No. Pin `@types/node` to the Node 22 runtime and ignore Dependabot majors `>=23` until `engines` / CI move. | Types for a newer Node expose APIs this process does not have. Closing #315 rather than merging. |
| #313 | May TypeScript jump 5.9 → 7.0? | No. Stay on TypeScript 5.9 and ignore Dependabot majors `>=7` until typescript-eslint supports the Go rewrite. | `npm ci` fails: `typescript-eslint@8` peers `typescript@>=4.8.4 <6.1.0`. A merge would need a supporting eslint release and a clean typecheck/lint/test/build with no workarounds. |
| #314 | How does `@vitejs/plugin-react` 6 typecheck against the workspace? | Hoist `vite` `^8.3.5` to the workspace root so there is one Vite copy (and one `Plugin` type). | Without the hoist, root Vite 7 (vitest peer) and console Vite 8 disagree on `Plugin` (`exactOptionalPropertyTypes`) and `console/vitest.config.ts` fails typecheck. |
| #273 | How is a coverage / browse scope read from a resource URI? | One `scopeOf(cloud, resourceUri)`: Azure `subscriptionOf` (`split("/")[2]`), GCP `projectOf` on the `projects` segment. PUT inventory and `filterInventory` use it and pick launch-check ids by cloud. | Cloud Asset names put the service at index 2 (`compute.googleapis.com`), so Azure parsing keys GCP coverage as `compute.googleapis.com:azure-…` and the `/subscriptions/` browse filter never matches a project. |
| #292 | How do inventory filter options and the subscription column stay correct across clouds? | Browse returns a typed `subscriptionOrProject` (via `scopeOf`) plus `cloud`. The console reads that field, builds owner/service/subscription/region options from the loaded rows, and shows the session org and those scopes in the header. | Hard-coded fixture options hide real regions and owners. URI index 2 is the GCP service, not the project. Issues already derives options from data. |
| #275 | What does the production default harvester return? | Throw `ProviderNotConfiguredError`. Fixture loaders stay injected by tests; demo uses the synthetic estate. Cost/commitment/budget POSTs do the same. Alerts analyse only a supplied cost series — never the replay file. Live Resource Graph stays leftover (#59). | `defaultHarvester()` parsed `docs/azure/ground-truth.json`, so every real org scan returned `disk-unattached`. A silent fixture default is a lie once a customer org exists. |
| #289 | How should coverage words be shown on the console? | Glossary in `docs/scan-contracts.md`. Screens import `TERMS` from `terms.ts`: **assessed / not assessed** for coverage, **undetermined** for check results. Blind spots has a State column for both. Issues says “assessed”, never “covered”. | “Covered” and “unassessed” were used for different things. The reader could not tell “not run” from “ran but could not decide”. |
| #285 | How should scheduler and Lambda tests stay isolated? | Fresh `MemoryStore` + app in `beforeEach`. Poll loops throw if the job never reaches the expected status. The Lambda handler forwards method, query and body so PUT and unknown-route tests can hit real routes. | A shared store made later tests depend on earlier ones. A GET-only handler could not be tested for PUT or query strings. |
| #290 | How does hash navigation stay accessible? | `document.title` is “Page - Farside”. | Releases | How does the monorepo version and tag? | One product version via `googleapis/release-please-action@v4`. Workflow permissions are `contents: write` and `pull-requests: write`. | One changelog and one tag match “one product”. A PAT and GitHub Pages demo-mode console are leftover — Pages waits on the #243 design pass. |
| GHCR | How are API and console images built and published? | Two images, two Dockerfiles. API: multi-stage `node:22-bookworm-slim`, non-root `node`, `HEALTHCHECK` via `GET /health`. Console: Vite build served by `nginxinc/nginx-unprivileged` on 8080 (not by the API). Push `ghcr.io/zdemanche/farside-api` and `farside-console` on `v*` / published release with semver + `sha-` tags, `GITHUB_TOKEN` `packages: write`, buildx GHA cache, provenance `mode=max` and SBOM. PRs build only. | Separate images keep the SPA and API independently deployable. Slim (not distroless) keeps a Node HEALTHCHECK. nginx-unprivileged is the usual non-root static server. GitHub Pages demo console stays leftover until #243 dependents land. |
| #274 (part of #269) | How is the backend shipped to Lambda, and who may set the session headers? | esbuild bundles `backend/src/{index,lambda,scheduled}.ts` into `backend/dist` (`lambda.mjs`, `scheduled.mjs`); the eight `docs/**/*.json` fixtures are static imports, so the bundle runs without `docs/`. The adapter maps the whole Function URL event (method, path, query, headers, cookies, base64 body) and maps back status, headers, `set-cookie` as `cookies`, and base64 for non-text bodies. It strips `x-farside-org`, `x-farside-actor` and `x-farside-operator` unless `FARSIDE_TRUST_EDGE_HEADERS=1`. The Function URL is `AWS_IAM` and is not behind CloudFront: the distribution serves the console only, and `assertAuthenticatedEdge` fails the plan for `NONE` or for any distribution behavior routing API paths to the Function URL without a viewer authenticator. The operator token is an SSM SecureString read once per cold start (fail closed), not an env var. An EventBridge Scheduler schedule (`rate(15 minutes)`) invokes `scheduled.mjs`, which sweeps retention, ticks every non-demo org and waits up to 240 s for the scans it started. The stack has no custom domain or SPA error fallback. | Forwarding client-supplied session headers from a public URL, or routing through an OAC that always signs, makes those headers the trust boundary, so `/v1` stays closed until Identity (#48) can authenticate viewers. A scan started in a Lambda is frozen when the handler returns, so the tick waits for it. A distribution-wide 403/404 to `index.html` fallback would rewrite API errors, and the ACM certificate and hosted zone are not provisioned here. **Leftover (#269):** stuck-scan timeout, first-retry delay and per-decision metrics and alarm. |

Deploy to a dedicated AWS account and iac-hub `PRODUCTS` registration are **switch-on-later integrations**, not blockers. Missing credentials skip those workflows; they do not fail the required CI check.
